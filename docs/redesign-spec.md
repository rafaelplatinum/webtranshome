=== H. LUPA PASSWORD DENGAN OTP WHATSAPP (ringkas) ===
Alur: /lupa-password (pilih saluran WhatsApp atau email, isi nomor/email) → /lupa-password/verifikasi (OTP 6 digit) → /reset-password → pesan sukses → /masuk. Link "Lupa password?" di /masuk disambungkan ke sini. Layout dua kolom sama dengan /masuk. Backend: migrasi baru (phone_verified_at, nomor ternormalisasi 62xx unik, tabel otp_challenge, tabel password_reset_token). Endpoint: POST /api/auth/password/forgot (respons SELALU generik dan waktu respons mirip; OTP hanya dikirim bila akun ada dan nomor TERVERIFIKASI atau email milik akun), POST /api/auth/password/verify-otp (terbitkan reset token CSPRNG ≥32 byte, kedaluwarsa 10 menit, sekali pakai, disimpan sebagai hash), POST /api/auth/password/reset (validasi password sesuai aturan yang ada, simpan hash, CABUT semua sesi, kirim notifikasi perubahan password). Verifikasi nomor di halaman akun: POST /api/member/phone/request-otp dan /verify; mengganti nomor mereset status verifikasi. Aturan OTP: 6 digit CSPRNG disimpan sebagai HMAC hash, kedaluwarsa 5 menit, maks 5 percobaan, sekali pakai, OTP baru membatalkan yang lama, jeda kirim ulang 60 detik, batas 3 per jam per nomor/email dan per IP serta batas harian, constant-time compare, jangan membocorkan apakah akun ada. Akun Google-only boleh menetapkan password lewat alur ini. Pengirim lewat antarmuka WhatsAppSender: pakai gateway yang sudah ada di project; bila tidak ada, buat mock yang mencetak pesan ke log lokal plus implementasi nyata via env. Template: "Kode verifikasi Trans Home: {kode}. Berlaku 5 menit. Jangan bagikan kode ini ke siapa pun." Token reset tidak ditaruh di query string. Audit log tanpa kode/token/password. Test lengkap (OTP salah/kedaluwarsa/melebihi percobaan/dipakai dua kali, rate limit, respons identik, nomor belum terverifikasi, token reset kedaluwarsa/dipakai ulang, sesi lama dicabut).
